## NOVA has no local instance

NOVA runs on **BYM-AAPP01** under IIS. There is no dev database and no local
copy — `npm run dev` will not give you working data. Deploy is
`deploy\deploy.ps1 -Branch nova-codex`, **run on the prod box**, per
`.claude/skills/deploy.md` in that repo.

Consequence for VANTAGE work: **never validate NOVA SQL by deploying it.** Put
the queries in a service under `src/server/services/`, keep the route a thin
wrapper, and add a `scripts/validate-*.ts` that imports the same service and can
be run on AAPP01 with `npx tsx`. That way a query is proven against live data
before the route carrying it ships, and there is no second copy of the SQL to
drift. `scripts/validate-flow-signals.ts` is the worked example.

## Deployment

Pi 5, alongside NEURO and SARA. Copies the SARA pattern exactly.

- PM2 app `vantage-backend`, repo `/mnt/data/vantage`, user `nickw`, **port 3006**.
- **Node 22.22.2 is a hard pin** (`/home/nickw/.nvm/versions/node/v22.22.2/bin`).
  Node 20 segfaults `better-sqlite3`. Non-interactive SSH has no node/npm/pm2 on
  PATH unless you export it first.
- Express serves the built Vite frontend in production — one process, one port.
- Public frontend is a **Netlify** static build at `vantage.nickward.co.uk`; the
  API is the Pi's Tailscale Funnel URL. Tailscale Funnel cannot serve a custom
  domain, which is why the frontend is split out.
- Deploy is manual: `git pull --ff-only`, build frontend, run tests,
  `pm2 restart vantage-backend --update-env`. **Never pipe a deploy step through
  `head`/`tail`** — it hides a failed pull behind a zero exit status. Confirm
  with `git log --oneline -1` on the Pi.
- **`pm2 save` immediately after any `pm2 start`**, or the app vanishes on the
  next daemon reload.

### Auth — the one place we deliberately differ from NEURO

NEURO's API defaults to **fully open** when its PIN env var is unset. VANTAGE
must **refuse to start** if its auth secret is missing. It holds the coaching
layer, and the API is reachable from the public internet via Funnel. There is no
dev-mode exception — set the var locally too.

## The honesty rule

Inherited from `weekly-risk.js` and non-negotiable, because the audience for
this work is the person assessing Nick's PIP:

> A source that did not answer renders as **absent**, never as a healthy zero.
> A section nobody filled in says so. Zero overtime is a claim; no overtime
> figure is an absence.

Any new signal must carry whether it answered. Never let a failed query render
as good news.
